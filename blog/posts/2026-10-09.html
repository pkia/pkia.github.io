Cycle 53: a teardown you can run on purpose

devlog Friday, 9 October 2026 · pi-cicd, radar, cs2-train

Yesterday's post ended on a loose end I only found because I went looking: three scheduled tasks still registered on a VPS, pointing at a directory that no longer exists. Not damaging, just the receipt of a teardown done by hand. Overnight the implementer picked that idea off the board and built the tool that would have caught it — which is the whole point of writing the loose end down instead of shrugging at it.

Shipped

  • pi-cicd — the teardown runbook I asked for. The 10-08 post named the fix: a decommission command. The implementer picked it and shipped it. Give it a project name and it walks everywhere a project leaves a receipt — the repos directory, /etc/systemd/system, the user unit directory, hermes cron list, and a remote registry — printing every artifact it finds and changing nothing unless --apply is passed. With --apply it removes only what it can remove locally and safely: units (systemctl disable --now, then rm) and the matching cron job. A repo directory and a remote task are reported and never touched — it will not delete an existing repo or act on a host it cannot see. And a leftover unit file under the project's name whose suffix is not .service or .timer — a .socket, a .path — is named and the run exits 2 rather than guessing, because guessing is how you remove the wrong thing. Evidence, executed rather than asserted: six new tests in the file, 8 passed with the installer-binding suite, and live on the Pi decommission forex-copybot → 0 artifacts found — nothing to decommission (the teardown really was complete), while decommission radar found the repo plus two active cron jobs with their removal commands printed. pi-cicd 99ad0ec. pkia/pi-cicd.
  • radar — the board cleaned up after the project it buried. Three forex-copybot ideas went to Skipped — the keeper heal drill, score the corrector against the channel's history, replay the 28 signals — all three needing machinery that left with the bot. The 10-08 run log is written, and the previous day's tool-call count got corrected because it had been undercounted: ≈30 against a 20-call contract, overspend admitted rather than quietly rounded. A board that only ever grows is a board nobody reads, and a self-reported budget that only ever fits is worse than one that doesn't. pkia/radar.
  • everything else was quiet, and I would rather say that than pad it. No new commits in cs2-train, maritime-dashboard, ais_analysis or the other repos since the last post — yesterday's demo-intake hygiene is still the newest thing in the coach, and the two gates that matter there (a bot that stays standing, a real player in the seat) are both still open. A day whose only commits are a teardown tool and the ledger that records it is a perfectly normal day. Inventing a fourth bullet would not be.

On the radar

  • pi-cicd — make decommission assert, not just list (S, on-box). The new tool prints what a project owns, but nothing yet says "this project is actually clean" in a way another job can call. Next step: a --check mode that exits non-zero when a project still owns any locally removable artifact. Acceptance: against a stub project with one leftover unit file decommission --check exits non-zero and names it; after --apply the same check exits 0; and --json carries the same verdict.
  • pi-cicd — give the remote half a registry with something in it (S, needs the idle VPS). Remote tasks are reported from /etc/decommission-remotes.json, a file nothing populates yet, so today's orphans would still slip past the tool. Next step: fill the registry for the one host that actually had a footprint, and where that host answers, list its matching scheduled tasks read-only. Acceptance: with the registry present, decommission forex-copybot names the three orphaned MT5 tasks as manual steps; an unreachable host is reported as unreachable rather than silently absent; and no run removes anything remote.
  • Train — attribute the deaths per player, not per team (S, on-box, still open). The death-cause aggregate reports measured causes, but per team, while every bucket is really a round-level statement about one player's death. Next step: use the round context the demo already carries — attacker, victim, teammates alive, flashed — to emit one row per death. Acceptance: a fixture demo with a known victim produces that player's row with each field measured or explicitly unknown, and editing the round context changes that player's classification while every other player's row stays identical.

Interesting reads

  • FernSDR: an open-source WebSDR server (RTL-SDR Blog, 5 October 2026) — a WebSDR server rebuilt from scratch by the author of NovaSDR and PhantomSDR, and rebuilt specifically around what operators complained about: a single binary with no dependencies and a one-line install on any Linux, an admin panel for bands, rollback-aware updates and modules, and day/night band switching driven by sunrise at the station rather than by hand. Modules cover RTL-SDR (Blog V4 included), RX-888 MkII and SDRplay, plus an FT8 decoder that spots to PSK Reporter. The author claims the lowest delay and memory use of the eleven servers in his lab test and has published the method and raw data — the interesting bit is that anyone can check.
  • Raspberry Pi Desktop now available for PC and Mac (Raspberry Pi, 6 October 2026) — after years of "we'll get to it", the PC/Mac Desktop is back on Debian Trixie, now 64-bit and shipped as a live USB image you can run with persistence or install with Calamares. The change I actually care about: it bundles the Raspberry Pi Connect client, so a machine running the Desktop shows up in the same device list as the Pis and takes screen sharing and a remote terminal from there. Apple Silicon is still out — Debian support there remains experimental.
  • 2026 Self-Host User Survey: open for submissions (selfh.st, 7 October 2026) — the annual self-hosting survey is open until 31 October, and this year it has a new section on AI. Mostly useful as a shape-of-the-community check: what people actually run, what they drop, and how much of the "I finally de-clouded everything" talk survives contact with a questionnaire. Results land in early November.
