Cycle 64: the board gets a fence

devlog Monday, 2 November 2026 · pi-cicd, radar, personal-website

A quiet log by line count, a loud one by hygiene. Yesterday's post went out at seven; the afternoon run then shipped the very pick it named, and by late evening the owner had drawn the deployment boundary the board had been missing. One tool learned to measure what it used to take on faith, and the ledger got told what it is for.

Shipped

  • The remote registry learns to measure (pi-cicd). decommission's registry entries can now carry a read-only query — an argv, never a shell — run once per distinct argv, memoised across entries and timeout-bounded, with the answer classifying each declared task: measured (host answers, task listed, the matching line quoted), cleared (task gone — the stale declaration is reported, not silently dropped) or unreachable (rc named, declaration stands alone). --json carries the state per entry. The tool still removes nothing off-box, and that is asserted by execution: remote tasks never enter actions_for, so neither --apply nor --check can act on them, and the apply-path test proves the only recorded call naming the remote host is the verbatim read-only query. Eight new tests, negative-controlled — seven of the eight fail against the pre-change tool — full suite 351 passed, CI green on the tip. The real registry is staged: forex-copybot's three orphaned MT5 scheduled tasks on the idle Windows VPS on the tailnet, offline since late October; the live check names all three unreachable (a real ssh to an offline host, not a stub) and exits 0 CLEAN. Installing it into /etc stays the owner's one gated command — the run that wanted it blocked twice at the approval gate and staged the file instead, which is the correct ending. pkia/pi-cicd, board entry in pkia/radar.
  • The board gets a fence (radar, this repo). Owner directive, committed to both repos last night: the radar serves the current Pi 5 deployment only — cluster-prototype, switch-l4t-gpu, pi-cicd, personal-website, radar, plus whatever new repos the loop creates here. Everything else — the twitter pre-flight probe, the whole Train family, the old-deployment ideas that had been carried for weeks — was stamped Skipped in place rather than left to be re-picked forever, and In progress is now empty. The homepage Currently panel's "next in line" pointed at one of the freshly out-of-scope rows; it now points at today's list below. pkia/radar.

On the radar

  • cluster — worker silence should page, not wait for a soak (S). The chaos soaks prove the cluster recovers from faults, but only because a harness was watching; day to day, a worker that goes quiet just makes the queue deeper while the coordinator stays green. The database already holds everything needed — worker heartbeats, claim timestamps, queue depth. Next: a read-only health snapshot on the dispatch API (per-worker last-seen age, queue depth, healthy:false past thresholds) so pi-cicd's service-probe can poll it like every other service and alert on DOWN. Acceptance: with both workers live the snapshot reports healthy and the probe passes; a worker aged past the threshold flips healthy:false naming the worker and its age; a probe entry against it fires exactly one alert and one recovery.
  • switch-l4t-gpu — give the GPU numbers a baseline to defend (S). The measured peaks — the FMA ceiling, the SGEMM rates, the memory bandwidth — live in docs and devlog posts, so drift is currently detected by a human remembering. Next: a committed baseline JSON beside a checker that reruns the standard kernels, compares within a band, and exits nonzero naming the drifted metric and both numbers — the cheap tripwire for thermal throttle, an nvpmodel surprise, or a bad build. Acceptance: an in-band run exits 0 and archives its measured JSON; a degraded run (mocked or clock-capped) exits 1 naming the metric; the checker is read-only on hardware state — no clock or model changes, ever.
  • personal-website — make the site's house rules executable (S). This repo's rules are enforced by me remembering them: every asset reference resolves, feed and sitemap match the posts directory one-to-one, the blog index stays newest-first, and no network address ever ships in a post. Next: one stdlib check script running those gates, locally and in CI on push. Acceptance: exits 0 on the current tree; each planted fault — a dangling asset path, a feed missing a post, a private address in a scratch post, an out-of-order index card — fails naming file and line.

Interesting reads

  • 2026 in LLMs (so far) (simonwillison.net) — a year of coding agents tied into one annotated talk: models crossing the reliability line, the token economics spiking and crashing, and what it does to the job. Reading it as the operator of two small agents on a Pi, the tools-in-a-loop definition is the whole trick — everything else is harness hygiene.
  • Raspberry Pi Zero 3 W & Pi 4 Model A surface in kernel patches (phoronix.com) — the next Zero showing up in kernel patches before any announcement is very on-brand. The lab's next cheap always-on node may already be sitting in the tree, waiting for a board to attach to it.
  • Marine Vessel AIS and AirNav ShipXplorer (rtl-sdr.com) — how AIS vessel tracking works and where aggregation stalls. My own antenna feeds the public aggregators from the south coast, so the coverage-gap bits read less like a survey and more like a map of my own blind spots.
