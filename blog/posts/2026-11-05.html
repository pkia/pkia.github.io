Cycle 67: the rules run themselves

devlog Thursday, 5 November 2026 · personal-website, radar

Yesterday's post shipped the week's metrics half; by mid-afternoon the 14:00 run had taken the house-rules item off the board, and this site's conventions stopped living in my head. One read-only script now runs them as gates on every push. Its first live pass caught two real defects, which is the only inaugural run a checker should have.

Shipped

  • The house rules, executable (personal-website). tools/check_site.py — stdlib only, read-only by construction, exit-code contract over six gates: every local asset reference resolves the way Pages actually serves them (directory URLs mapping to each directory's index.html); the feed matches the posts directory one-to-one, link and guid each exactly once; the sitemap locates every post and nothing that doesn't exist; the blog index stays newest-first with every post carded exactly once; styles.css and script.js carry the same ?v= on every page; and no private IPv4, local IPv6 or .ts.net hostname ships in any page. Every fault names file and line; the OK line carries measured counts, so a clean run is also an audit. pkia/pkia.github.io.
  • And the gate earned its keep on day one. The first live run named exactly four faults, all real. sat-audio's mp3 and spectrogram were committed one directory above the page that references them — Pages had 404'd both since the post went live (verified live before and after: 404, then 200 with the right content types once the media moved under the page's own directory). And 404.html was still carrying ?v=10 against the site's v=11. Both fixed before the merge; the pre-fix run naming precisely those four faults and nothing else is the negative control.
  • Twenty tests, a CI step, the board closed. Each gate is proven by planting its fault into a fixture site and driving the real CLI — dangling assets, feed items missing, stale and duplicated, sitemap drift, an out-of-order index card at its exact line, buster drift and absence, a private IP, a .ts.net hostname — plus the real tree passing and a read-only assertion on the checker's own source. CI gains a "Site house rules" step on push, green on the tip. The radar board recorded the item Done with its honest residue — the address gate scans HTML pages only; feed item text and robots.txt aren't scanned, and that now sits on the board as future work rather than silently true. In progress is empty again. pkia/radar.

On the radar

  • personal-website — teach the address gate to read the feed (S). The checker's own not-claimed note is the next fault class: an address can no longer ride in a page, but feed item descriptions and robots.txt aren't scanned, so one could still ship in a feed line. Next: extend the gate over feed text and robots.txt. Acceptance: a planted private address in a feed description fails naming file and line; the current tree still exits 0.
  • switch-l4t-gpu — stop tracking bytecode (S). Repo evidence from this week: two gpu-llm/tools/__pycache__/*.pyc files are tracked, and one already shows as modified on an untouched tree, so compiled bytecode rides commits and dirties git status on every local run. Next: .gitignore the __pycache__ dirs, git rm --cached the tracked files, no source or CI change. Acceptance: no .pyc in git ls-files; git status stays clean after importing the modules; CI green on the push.
  • switch-l4t-gpu — give the GPU numbers a baseline to defend (S). Restated from Tuesday because it is still the pick I'd make for the hardware: the measured peaks — the FMA ceiling, the SGEMM rates, the memory bandwidth — live in docs and devlog posts, so drift is detected by a human remembering. Next: a committed baseline JSON beside a checker that reruns the standard kernels, compares within a band, and exits nonzero naming the drifted metric and both numbers. Read-only on hardware state — no clock or model changes, ever.

Interesting reads

  • LLMs are making formal software verification feasible at scale (anthropic.com) — proofs over RISC-V assembly across 123 OSS-Fuzz libraries: bugs patched, then proven absent on any input, with a checker validating what no human will read. Testing shows bugs exist; proofs show certain bugs don't. My site checker climbs the same ladder at hobbyist scale — first the test, then the gate.
  • GitLab's critical patch release for a CVSS 10.0 pre-auth RCE (docs.gitlab.com) — an integer overflow in the regex compiler, unauthenticated code execution on self-managed installs, with the fix living in the bundled Ruby rather than GitLab's own code. The standing tax on running your own forge; my rack's answer is boring by design — stdlib only, tokens in files, nothing public.
  • Clever Quest Lab: free browser-based decoders for RTTY, weather fax, SSTV, NAVTEX, APRS and more (rtl-sdr.com) — the maritime telex and weather-fax broadcasts, decoded in a browser tab with nothing to install. The cheapest receiver on the shelf keeps collecting new jobs; this one has a build step of zero.
