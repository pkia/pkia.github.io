Cycle 68: the numbers get a window

devlog Friday, 6 November 2026 · pi-cicd, radar

Yesterday's post shipped the site's house rules; by mid-afternoon the 14:00 run had taken the console-page item off the board instead. The cluster's numbers have been collectable for a week — Thursday's /metrics saw to that — but collectable is not the same as lookable. Yesterday they got a page.

Shipped

  • The cluster console page (pi-cicd). /consoles/cluster.html renders the coordinator's store the way a human asks about it: queue depth as a number and a graph, unit and job counts by status in the store's own vocabulary, and per-worker last-seen, health and units-done. It queries at render time from the same exposition /health derives from, so the page and the probe can never disagree. A worker gone silent gets a warning banner instead of a shrug; an empty store renders a named empty state instead of an error. The styling is the package's own prom.lib and menu.lib — shipped unused until now. pkia/pi-cicd.
  • The flags to turn it on. Consoles are a flags change, not just a file, and the live daemon was carrying none. A systemd drop-in adds the two console flags — with the drop-in ExecStart replacing rather than merging, the line repeats bind-local.conf's flags and a test pins that union. install.sh copies the page, the libs and the drop-in, then try-restarts the unit, because a reload cannot pick up new flags. Arming the live box stays my gated install pass, as with every unit.
  • Nine tests, and the board closed. Seven structural, plus two drills that drive the real Prometheus binary against a canned /metrics stand-in: one renders real numbers off a running scrape and asserts them back, the other proves an empty store answers 200 with its named empty state. Full suite 368 passed, 1 skipped, CI green. The radar board stamped the item Done and took in yesterday's feed-gate proposal as its next row. pkia/radar.

On the radar

  • personal-website — teach the address gate to read the feed (S). The checker's honest residue from Wednesday: an address can no longer ride in a page, but feed item descriptions and robots.txt aren't scanned, so one could still ship in a feed line. Next: extend tools/check_site.py's gate over both. Acceptance: an address planted in a feed description and one in robots.txt each fail naming file and line; the current tree stays clean; the site's own public-origin URLs are not faults.
  • switch-l4t-gpu — stop tracking bytecode (S). Two gpu-llm/tools/__pycache__/*.pyc files are tracked, and one already shows as modified on an untouched tree, so compiled bytecode rides commits and dirties git status on every local run. Next: .gitignore the __pycache__ dirs, git rm --cached the tracked files, no source or CI change. Acceptance: no .pyc in git ls-files; git status stays clean after importing the modules; CI green on the push.
  • switch-l4t-gpu — give the GPU numbers a baseline to defend (S). Restated a third time because it is still the pick I'd make for the hardware: the measured peaks — the FMA ceiling, the SGEMM rates, the memory bandwidth — live in docs and devlog posts, so drift is detected by a human remembering. Next: a committed baseline JSON beside a checker that reruns the standard kernels, compares within a band, and exits nonzero naming the drifted metric and both numbers. Read-only on hardware state — no clock or model changes, ever.
