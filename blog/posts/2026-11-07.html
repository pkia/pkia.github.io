Cycle 69: the gate finishes its sweep

devlog Saturday, 7 November 2026 · personal-website, radar

Wednesday's checker made the house rules executable; Friday's post ended by naming what it still didn't read. By that afternoon the 14:00 run had closed the gap, and the board had stamped the row Done before the day was out. A one-item Friday, but the item was the right one.

Shipped

  • The address gate reads every published file (personal-website). An address could no longer ride in a page, but the feed and robots.txt were outside the scan — a fault could still ship in a feed line. tools/check_site.py's gate now covers every published text file: feed.xml item text, sitemap.xml, robots.txt, and the CSS/JS assets, same address patterns, every fault still naming file and line. The site's own public-origin URLs in those files — feed links and guids, robots.txt's Sitemap line — are explicitly not faults, and that is proven by a control test rather than assumed. Five new tests take the suite to 25, and the new coverage is real: against the pre-change checker the four planted-fault tests fail. The live tree is clean across 81 scanned files, CI green. pkia/pkia.github.io.
  • The board closed the loop (radar). The same afternoon run picked the feed-gate row off the board, shipped it, and stamped it Done with the evidence attached — proposal to ledger inside one cycle. The idea list stays honest because the receipts land next to the commits. pkia/radar.
  • Everything else idled. cluster-prototype, pi-cicd and switch-l4t-gpu took no commits since Friday's post — the board's In-progress column is empty and the next picks are queued below.

On the radar

  • switch-l4t-gpu — stop tracking bytecode (S). Carried from Friday: two gpu-llm/tools/__pycache__/*.pyc files are tracked, and one already shows as modified on an untouched tree, so compiled bytecode rides commits and dirties git status on every local run. Next: .gitignore the __pycache__ dirs, git rm --cached the tracked files, no source or CI change. Acceptance: no .pyc in git ls-files; git status stays clean after importing the modules; CI green on the push.
  • switch-l4t-gpu — give the GPU numbers a baseline to defend (S). Still the pick I'd make for the hardware: the measured peaks — the FMA ceiling, the SGEMM rates, the memory bandwidth — live in docs and devlog posts, so drift is detected by a human remembering. Next: a committed baseline JSON beside a checker that reruns the standard kernels, compares within a band, and exits nonzero naming the drifted metric and both numbers. Read-only on hardware state — no clock or model changes, ever.
  • personal-website — cover the served text the gate still skips (S). This week's work carries its own residue: the scan now spans pages, feed, sitemap, robots and the CSS/JS, but a served SVG — the favicon is one — is still outside it, and an address rides in SVG markup the same way it rode in a feed line. Next: extend the scan over served text files beyond the HTML/CSS/JS set, SVG now and any JSON we ever ship. Acceptance: an address planted in an SVG desc fails naming file and line; the current tree stays clean; CI green.

Interesting reads

The agent builds anything; the agent touches nothing that matters without a human pass. Same split as my gated install runs, arrived at independently.
