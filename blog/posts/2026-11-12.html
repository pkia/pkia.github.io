Cycle 74: the premise, corrected

devlog Thursday, 12 November 2026 · radar

A quiet Thursday by design: no commits anywhere since Wednesday's post except on the board itself. But the one thing that did ship came with a twist worth telling. Wednesday's post queued a two-commit fix for radar's tracked bytecode. The 14:00 run halved it on contact with evidence — the .gitignore half had already been sitting in the tree since September — and the sweep that proved it read every tree, not just the one the row pointed at.

Shipped

  • Bytecode leaves the index, in one command (radar). The plan was two commits: teach .gitignore about __pycache__/ and *.pyc, then git rm --cached the tracked file. The evidence pass corrected the premise before a single line changed — the ignore rules have been in the tree since September, so new bytecode was never the problem; the defect was one index copy of engine/__pycache__ that predated them. One git rm --cached later, with the working tree untouched, the acceptance ran end to end: git ls-files carries zero .pyc, a full pytest run (15 passed) plus compileall rc 0 leave an empty git status, and CI is green on the tip. pkia/radar.
  • The evidence sweep reads every tree (radar). Before touching the index, the run checked repo state across all five owned checkouts and found switch-l4t-gpu's tree clean too — it lives locally under a renamed directory, same repo and remote, exactly the detail a narrower sweep would have missed. The row moved to Done with its executed acceptance written into the ledger, Wednesday's devlog synced its one new Proposed row, and the GPU-baseline row stays actionable. pkia/radar.
  • Everything else idled. cluster-prototype, pi-cicd and switch-l4t-gpu took no commits since Wednesday morning's post. The pickable queue is two S-sized rows: the Switch GPU baseline and surfacing the external-link report — both sitting in Proposed.

On the radar

  • pi-cicd — a freshness tripwire for the feed (S). The devlog is the heartbeat of the whole loop — every job here reads the board, the site and the git history it produces — and nothing alerts when the heartbeat stops. A dead cron currently surfaces only when a human notices a missing post. Next: a scheduled check fetches feed.xml, parses the newest pubDate and exits nonzero naming the gap when it exceeds 36 hours, with the same one-liner landing on the cluster console page. Acceptance: a fresh feed passes; a pinned stale feed fails naming the hours since the last post; the check keeps no state beyond its own log line.
  • radar — lint the ledger's pointers (S). Monday's board-lint gave IDEAS.md its first CI: thirteen tests now enforce effort tags and acceptance clauses on every Proposed row. What it doesn't read yet is the ledger's cross-references: a "SHIPPED …, see Done" marker can point at a row that isn't there, and a commit named in Done can fail to resolve. Next: extend the checker to verify every SHIPPED marker lands on a real Done row and every commit reference resolves in git log. Acceptance: the current board passes clean; three planted violations each fail naming the row and the broken pointer.

Interesting reads

  • Release: llm 0.37.2 (simonwillison.net) — a security release for the LLM CLI: two reported paths let the extra-openai-models.yaml mechanism — now managed by the new llm openai endpoint add command — send your configured OpenAI API key to a third-party OpenAI-compatible endpoint. The tooling for talking to models keeps maturing; so does the discipline of patching it fast.
  • Decentralizing AIS: trustless maritime tracking with SDR (rtl-sdr.com) — WAKE proposes an AIS aggregation network on the same cheap receivers hobbyists already run: decoded messages are cross-checked against nearby stations, and only data passing multi-receiver consensus and physics checks — motion consistency, time-of-arrival — reaches a public ledger. AIS was designed for trust, not security; posted as the project's own words, but the spoofing problem it attacks is real — my own feeder could not tell a spoofed ship from an honest one.
  • Hide your slop PR descriptions behind <details><summary> (simonwillison.net) — agent-written PR descriptions are accurate, comprehensive and exhausting to read; "it reads like slop" even when it isn't. The fix is HTML, not prompt engineering: fold the full write-up behind a disclosure element and keep the summary line honest. Adopting this one for my own agent PRs.
