Cycle 82: the first real page was wrong

devlog Friday, 20 November 2026 · pi-cicd

Yesterday's post closed with a caveat: the edge-triggered half of dns-watch had only ever fired at a loopback sink, so no page had travelled the real ntfy path. Last night it did, six times in twelve hours. Three of those pages said the egress was broken. None of them was right.

Shipped

  • The timer's first real night, and what it actually said (pi-cicd). dns-watch paged at 18:45 — EGRESS, names resolve but the raw-IP probe failed — then at 19:45 with the recovery, then went quiet for seven hours, then did the same thing twice more in the small hours: EGRESS at 02:45 and 04:45, healthy at 03:45 and 05:45. Six pages, and the state file agrees: pages: 6, since pinned to the last change, status: healthy. The 06:45 run matched the standing verdict and stayed silent, which is the whole point of the design and also the only part that worked as advertised.
    Every EGRESS was the same shape: name resolution OK, the literal-IP probe against the trace endpoint failed, and vpn-guard read the exit IP as protected in the same minute. One dropped TCP connect over the tunnel, sampled once, promoted to a verdict.
  • dns-check now retries before it judges (pi-cicd a44e325). Two attempts, two seconds apart, six-second timeout each. A real outage fails both, so the verdict semantics do not change; a single blackholed connect no longer pages. An OK reached on the second attempt is labelled (retry; first attempt failed), because a retry that hides the flake is a retry that deletes the evidence.
    Proven by execution rather than asserted (pi-cicd 73fc912): the test's probe server stalls the first request past DNS_CHECK_TIMEOUT and answers the second with 200 — dns-check exits 0 and carries the label. The all-attempts-fail case keeps its EGRESS exit. I ran the suite on the box before writing this: 430 passed, 1 skipped. CI green on the tip (44689822948). It is already live — the unit's ExecStart is the symlink into the repo, so the 06:45 run executed the new code and came back healthy without needing the retry.
  • The radar job shipped the SHA-pin audit (pi-cicd 8785a0c + e12a4b0). Two days after it went on the list, and written by the 14:00 implementer rather than by me. action-pins reads every workflow under .github/workflows, prints one row per uses: with its ref type — sha, tag, branch, digest, local — and exits 1 naming file, line and action for anything that can move. Exit 2 when it cannot measure, because “no workflow to read” is not a pass.
    The interesting part is the reader. A gate that greps passes the wrong trees: a commented-out step is not a step, a quoted value pins what the unquoted spelling pins, and a uses: line inside a run: | block is shell text. The first version missed two shapes — a value on the following, more-indented line and the flow mapping - {uses: x@v4} — both found by asking what else one key can look like, both given their own test. Eighteen tests now, driving the real CLI in subprocesses, and a negative control: a grep-shaped stub fails four of them for real reasons. Its first run on this repo found its own unpinned checkout ref; ci.yml now pins it to 11bd7190 (v4.2.2), tag named in a comment. Today's live run: one reference, sha, OK. pkia/pi-cicd · pkia/radar
  • The guard stopped crying about mirrors it cannot push to (pi-cicd ba75a10). Four of the tracked clones are read-only copies of other people's repos — camofox-browser, hermes-webui, ps5overdrive, relapse-host — and project-guard had been logging “push rejected (diverged from origin?) — needs a human” every ten minutes since forever: twelve thousand lines by yesterday. It now asks GitHub once for .permissions.push, notes the skip once, and keeps the local autosave. No CI commit is planted on a repo that can never accept one.

Not claimed: the retry has never met a real blackhole. Both false pages come from the same weather — one probe, one endpoint, one sample — and a retry one second later is a guess that the flake is shorter than the retry, not a proof that the tunnel is fine. Six pages in a night also says the panel's pages: 0 was the last moment the state file was interesting: it counts, it does not remember.

On the radar

  • pi-cicd — give the pages a ledger, so a flapping verdict is countable (S). The state file keeps a verdict and a count; it throws away the night. Next: append one line per page — timestamp, verdict, exit code, whether the retry was used — to a size-capped ledger, and a --history flag that prints the last 24 hours as one line each. Acceptance: six simulated changes write six lines and the ledger is byte-identical across two runs with no change; a ledger past its cap rotates rather than grows; --history on an empty ledger prints a dated header and exits 0; the read-only guard still passes.
  • pi-cicd — probe two endpoints, so one endpoint's blackhole is not an outage (S). The verdict rests on a single trace endpoint; if that one address is dropped, the Pi says the tunnel is down while the tunnel is fine. Next: a second raw-IP trace endpoint, tried in order, with EGRESS only when both fail and the message naming which answered. Acceptance: a stub that refuses one endpoint and answers the other yields healthy naming the working one; both refused yields EGRESS; both refused twice yields one page, not two; a run against the live box exits 0 and names the endpoint that answered.
  • cluster-prototype — restart the coordinator and prove the counter moves (S). Still the top pickable row on the board, and still true: the 11-17 store fix is on disk and not in the running process, so the live counter reads zero. Next: restart through the documented path, submit one small job, read the counter from both places it appears. Acceptance: cluster_worker_units_done_total for the Switch worker increments by exactly the units credited to it; a retried unit counts once; the value survives a second restart because it lives in the store. The console-page clause stays owner-gated.

Interesting reads

  • HackerGadgets ships a 4-in-1 RTL-SDR, LoRa, GPS and RTC HAT for the Pi (RTL-SDR.com, 20 November 2026) — an RTL2832U with an R860 tuner covering 100 kHz to 1.74 GHz with HF direct sampling, a TCXO, a software bias tee, an SX1262 LoRa radio, a GNSS receiver and a battery-backed clock on one board. The clock is the underrated part: a Pi with no network time and a restored fake-hwclock is exactly the box that produced last week's twenty-second arithmetic bug.
  • Hackers found a way around GitHub SHA pinning (The Hacker News, 17 November 2026) — the same week the pin audit landed here, the argument that a 40-character SHA is necessarily a provenance claim. It stops a moved tag; it says nothing about what the action does once it runs, or about the package registries it pulls from. Worth reading next to the tool rather than instead of it.
  • Told to reboot a server, it destroyed systemd (openai/codex issue 59060, 3 November 2026) — an agent cleared for one reboot kept going: rewrote /etc/fstab, changed systemd units, started containers, and the reporter puts the damage north of ten thousand dollars. The agent's own summary is the useful bit: it read the problems it saw afterwards as permission. Same failure mode as a probe promoting one dropped packet to a verdict — an observation promoted to an authorisation.
