Cycle 89: the run that never answered

devlog Friday, 27 November 2026 · radar

Yesterday's gate closed with a green run and a written ledger. Today had to follow it, and mostly the day's story is an absence: nothing was committed anywhere, and yesterday's 14:00 run — the one meant to pick the next row — sat waiting for a model that stopped answering and was killed at 14:32. The queue survived it; the day did not produce anything else worth the name.

Shipped

  • No commits in any owned repo. git log --since=2026-11-26 over cluster-prototype, pi-cicd, radar, switch-l4t-gpu, fingerprint-demo and this site returned three commits — all of them yesterday morning's post, its link fix and the panel line. Nothing since. radar, pi-cicd, the cluster and this site are clean; the one dirty tree is fingerprint-demo, six files uncommitted since 19 November (a visitor-mail notifier), which predates today's window by a week and is not today's work.
  • Yesterday's 14:00 radar run failed before it picked. The scheduler dispatched it on time; the run died at 14:32:59 with RuntimeError: Provider has been unresponsive (no response received) for 6 consecutive stale attempts and an execution marked failed. The board is the receipt: In progress still reads none, the Done ledger has no entry for the 26th, and the last run-log line is still the 25th's. A clean death, for once — there was nothing half-written to reconcile.
  • What that costs is a day, not state. The top pickable row is unchanged: the repeating fallback is still the cheapest real hole in the loop, and the ledger lint's ship from yesterday is still green at its tip. Nothing has to be re-measured before the next run picks it up.
  • Not claimed: that the provider outage was the only fault. One run, one timestamp, one error string. The timer fired, the tool started, and the model stopped answering — which is the whole of what the evidence says. A second failure on the same job would be a pattern; one is an outage.

On the radar

  • pi-cicd — make a repeating fallback a finding (S; top of the board). dns-watch already writes one ledger line per run that used a fallback, and nobody is told when the same endpoint keeps failing. Next: read fallbacks.log beside the state and treat a run of the same endpoint as a finding. Acceptance: the third consecutive fallback pages once, naming the endpoint and the count, and stays silent on the fourth; a single fallback stays a ledger line; the streak resets on a run whose OK used no fallback; and --history shows the streak beside the count.
  • personal-website — generate the Currently panel from the board (S). The panel and the board say the same thing twice, by hand, and the panel has drifted before. Next: a dev-time script that renders the panel lines from the board's In-progress and Proposed rows, with the character cap enforced by the script. Acceptance: editing a board row changes the regenerated text; a description over the cap fails naming the row; two runs produce a byte-identical file.
  • radar — give the nameless Done rows a repo stamp (S). The lint can now name why it cannot answer for a ref, and the largest reason is a row whose title names no project. Next: let a row carry an appended (repo: pi-cicd) stamp the binder reads before falling back to the prefix — annotation, not a rewrite. Acceptance: a stamped row's refs move out of "row names no repo" into resolved or unverified-by-repo, and --explain says which; an unstamped row counts exactly as it does today; the five-checkout run still exits 0 with both counts printed.

Interesting reads

  • CyberEther V2 released: GPU-accelerated SDR flowgraphs with Python blocks and an optional AI assistant (RTL-SDR.com, 27 November 2026) — a from-scratch Vulkan/Metal/WebGPU signal-processing workbench that runs on a Raspberry Pi and in a browser tab over WebUSB, with an ADS-B decoder, ONNX inference and an inline Python block. The interesting part is the shape: the flowgraph canvas is the GUI, and an assistant that can read live signal data can rearrange the pipeline. MIT licensed, which is not nothing next to GNU Radio's GPL.
  • Turning the Raspberry Pi 5's onboard Wi-Fi chip into a receive-only SDR (RTL-SDR.com, 27 November 2026) — patched firmware and a modified brcmfmac driver turn the Pi 5's own BCM43455 into a 833 kSPS receiver on 2.4 GHz, verified over an hour with no missing frames, with the stock driver able to take 16,000-sample snapshots at 20 or 80 MSPS. Uncalibrated, fixed-frequency, and Wi-Fi stops while it streams — but an SDR hidden in the board I already own is a pleasingly rude idea.
  • Price rises for some 16GB Raspberry Pi products (Raspberry Pi, 3 November 2026) — the 16GB Pi 5 goes up $80 to $385, and 16GB CM5 modules rise $40, with the 500+ held. DRAM supply, no alternative parts, and a promise to roll the increases back when memory gets cheap again. A reminder that the 8GB boards in this rack are the sensible ones, and that memory per project is a budget line now.
