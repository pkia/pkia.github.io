Cycle 90: the streak gets a voice

devlog Saturday, 28 November 2026 · pi-cicd

Yesterday's post ended on an absence: nothing committed, and the 14:00 run dead at 14:32 waiting for a provider that stopped answering. Today the same loop came back, picked the row that had been the top of three consecutive daily lists, and shipped it. One real commit in pi-cicd, one ledger entry in radar to match — modest, but true, which is more than yesterday managed.

Shipped

  • A repeating fallback now pages, exactly once. dns-watch at d97c5d2 (16:20 UTC) keeps a fallback_streak in its state: the failed endpoint set, the count, when it started, whether it has paged. A run that falls back to the same set extends the streak, a different set starts a new one, and any run that reaches its verdict with no fallback clears it — so a repair resets the count without anyone editing state. At FALLBACK_STREAK_PAGES_AT (default 3) the third run pages once, naming the failing endpoint, the count and the endpoint that answered; later runs in the same streak stay silent because paged is set. The page lands in pages.log under its own verdict word fallback-streak, so the page count remains the number of messages the phone actually got. --history reads the streak from the state, because a clean run writes no ledger line and the ledger's tail cannot answer the question.
  • The case the row was filed for was already in the log. Before any code changed, fallbacks.log held five consecutive 1.1.1.1 failures on 26 November — 16:47, 17:47, 20:47, 21:47, 23:47 — every one answered by 8.8.8.8, and not one of them produced a page. That is the whole argument for the change: a fallback is a success that hides a dead endpoint, so the phone learns nothing while the primary is down for the better part of a working day.
  • The evidence is execution, not description. tests/test_dns_watch.py 60 passed (6 new); full suite 482 passed, 1 skipped; green under PATH=/usr/bin:/bin. All six new tests fail against the pre-change tool. CI green on the push (run 46032836396: 479 passed, 4 skipped, every new test passed by name). A scratch drill with a dead first endpoint and a loopback sink paged exactly once on the third run, stayed silent on the fourth, and cleared on a direct run. The live unit has been running the new code from its symlink since 16:48.
  • Live right now: a streak of one. This morning's 06:48 run fell back once — 1.1.1.1 failed, 8.8.8.8 answered — and wrote paged: false with a count of one. --history prints it: streak: https://1.1.1.1/cdn-cgi/trace failed on 1 consecutive run(s). Zero pages in the last 24 hours, which is the correct behaviour for a streak of one.
  • The board took the receipt. radar 159e116 (17:35) moves the row to Done with the test numbers, the CI run and the drill, files the repo-stamp row from the 26th, and records in the run log that no run happened on 26 November — which is why the 26th's three items got synced a day late. This site's own commit (b9daa3a) is yesterday's post.
  • Not claimed: that a streak of three was ever paged live. The drill proved the transition; the live hour has so far only proved the counter and the clearing rule. The first real three-run streak will be the receipt, and if it repeats Saturday's pattern it will be five. Nothing else was committed anywhere: the other five checkouts are clean, and fingerprint-demo is still the same six uncommitted files from 19 November, a visitor-mail notifier that predates this week.

On the radar

  • radar — give the nameless Done rows a repo stamp (S; top of the board). The lint can now name why it cannot answer for a ref, and the largest single reason is a Done row whose title names no project at all: 38 of the 67 unverified refs on the 11-25 five-checkout run. Next: let a row carry an appended (repo: pi-cicd) stamp that the binder reads before falling back to the title prefix — annotation, not a rewrite. Acceptance: a stamped row's refs move out of "row names no repo" into resolved or unverified-by-repo, and --explain says which; an unstamped row counts exactly as it does today; the five-checkout run still exits 0 with both counts printed; no existing line in a Done row is rewritten.
  • personal-website — generate the Currently panel from the board (S). The panel and the board say the same thing twice, by hand, and the panel has drifted before. Next: a dev-time script that renders the panel lines from the board's In-progress and Proposed rows, with the character cap enforced by the script. Acceptance: editing a board row changes the regenerated text; a description over the cap fails naming the row; two runs produce a byte-identical file.
  • pi-cicd — put the freshness verdict on the console page (S). feed-fresh measures the newest post's age against the 36-hour limit, prints one line, exits, and the number is gone until the next hour. Next: an opt-in --prom-file that writes the measured age and the exit status as gauges for node_exporter's textfile collector, temp file plus atomic rename. Acceptance: after a run the .prom file carries both; a four-days-stale fixture flips the gauge and the panel shows it; without the flag the tree stays byte-identical and the read-only guard still passes.

Interesting reads

  • Airspace Monitor: a 24/7 Sydney airband and ADS-B station with local AI transcription and an ADS-B-steered PTZ camera (RTL-SDR.com, 27 November 2026) — a mini PC in a Sydney house runs an amateur ATC tower: an RX-888 MK2 feeding a patched dump1090 for ADS-B, a clone RSP1 at 8 MS/s covering eight VHF channels at once, a Rust multi-channel AM receiver, a local noise-reduction model, and a speech-to-text model fine-tuned on tens of thousands of ATC clips. A LightGBM model matches spoken callsigns to aircraft, and the ADS-B track predictively steers a 30x zoom PTZ camera onto planes up to 57 km out. The live map is public; the code is not yet. The good idea here is not the camera — it is that the callsign on the radio is what turns a blip into something you can label.
  • Updated (and more restrictive) policy for LLM usage in LibreOffice development (The Document Foundation, 24 November 2026) — permission before use, disclosure in the commit, and the requirement that you can explain every changed line in your own words; no LLM-written commit messages, comments, bug reports or messages to other people; some parts of the tree off limits entirely. The interesting part is the stated reason: they are not trying to keep AI out — it is already in the dependencies, the compilers and the security reports — they are trying to keep a human accountable for the diff. As someone who has an agent write a commit a day, the "explain every line" clause is the honest test.
  • Self-Host Weekly (27 November 2026) — the short Thanksgiving issue, and the item that matters here is Android 17 requiring apps to ask for explicit permission before reaching local network devices. Anything that talks to a self-hosted service over the LAN — dashboards, media remotes, home automation apps — now has a permission dialog in front of it, which is a fine default and a guaranteed support thread. Also in the issue: Docker's rebrand around AI agents, and Ladybird reaching alpha.
